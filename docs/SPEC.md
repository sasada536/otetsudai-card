## 1. システム概要

### 1.1 目的

家庭内の「おてつだい制度」を運用するため、Notion 上で管理しているタスク一覧から、**印刷して壁に貼る／記入する紙**を自動生成する。Notion を編集するだけで紙が更新される状態を作り、手作業でのレイアウト修正を不要にすることが目的。

### 1.2 全体構成

```
┌─────────────────┐
│ Notion DB       │  「おてつだいタスク一覧」
│ （手動で編集）   │  ※非公開・APIトークンが必要
└────────┬────────┘
         │ Notion API (HTTPS/POST)
         ↓
┌─────────────────┐
│ generate.py     │  Python 3.11 / 標準ライブラリのみ
│ （GitHub Actions │  手動実行（workflow_dispatch）
│   上で実行）     │
└────────┬────────┘
         │ 静的ファイル書き出し
         ↓
┌─────────────────┐
│ output/         │  index.html
│ （4ファイル）    │  stamp_print.html
│                 │  basic_tasks_poster.html
│                 │  tasks.json（機械可読データ）
└────────┬────────┘
         │ actions/upload-pages-artifact → deploy-pages
         ↓
┌─────────────────┐
│ GitHub Pages    │  https://<user>.github.io/<repo>/
│ （公開）         │  → iPhone 等のブラウザで開いて印刷
└─────────────────┘
```

### 1.3 構成要素

| ファイル | 役割 |
| --- | --- |
| `generate.py` | 取得・変換・HTML/JSON 生成のすべて |
| `data/sample_tasks.json` | 認証情報なしで動作を再現するためのサンプルデータ（架空の内容） |
| `.github/workflows/generate.yml` | 実行と Pages への公開 |
| `LICENSE` | MIT License（コードに適用） |
| `.gitignore` | `output/` と Python のキャッシュを除外 |
| `README.md` | エンドユーザー向けセットアップ手順・ライセンス表示 |
| `CLAUDE.md` | Claude Code 向けの開発ガイド |
| `docs/SPEC.md` | 本書 |

外部ライブラリへの依存は**ゼロ**（`os` / `sys` / `json` / `html` / `datetime` / `subprocess` / `urllib` のみ）。`requirements.txt`、`package.json` 等のマニフェストは存在しない。ビルド手順・テストコードも存在しない。

## 2. 入力仕様

### 2.1 環境変数

| 変数名 | 必須 | 内容 | 未設定時の挙動 |
| --- | --- | --- | --- |
| `NOTION_TOKEN` | ○ | Notion Internal Integration Secret（`ntn_` 始まり） | エラーメッセージを stderr に出力し `exit 1` |
| `NOTION_DATABASE_ID` | ○ | 対象データベースの ID（ハイフンなし 32 桁） | 同上 |

いずれもモジュール読み込み時に `os.environ.get()` で取得され、モジュール定数として保持される。存在チェックは `main()` の冒頭で行われる。

### 2.1.1 コマンドライン引数

| 引数 | 内容 |
| --- | --- |
| `--sample` | Notion に接続せず、`data/sample_tasks.json` を入力として使う |

`--sample` は**明示的なオプトイン**である。環境変数が無いときに自動でサンプルへフォールバックはしない。自動フォールバックにすると、CI で Secrets の設定漏れが起きた際にジョブが成功してしまい、架空のデータが公開されるため。

### 2.1.2 サンプルデータの形式

`data/sample_tasks.json` は、2.2 節の Notion スキーマではなく、3.2 節の**変換後の形式**をそのまま保持する。

```json
{
  "basic_tasks":     [{ "name": "...", "note": "..." }],
  "challenge_tasks": [{ "name": "...", "note": "...", "star": "★★", "price": 50 }]
}
```

### 2.2 Notion データベースのスキーマ

`load_tasks()` が参照するプロパティは以下の 5 つ。**プロパティ名（日本語）はコードにハードコードされている。**

| プロパティ名 | Notion 型 | 必須 | 用途 |
| --- | --- | --- | --- |
| `タスク名` | title または rich_text | ○ | タスクの名称。空の行はスキップされる |
| `タイプ` | select | ○ | `基本` / `チャレンジ` のいずれか。それ以外の値の行は無視される |
| `難易度` | select | — | 星の表示（例: `★★`）。空の場合は `★` が入る |
| `単価（円）` | number | — | 1 回あたりの金額。空の場合は `0` |
| `備考` | rich_text | — | 補足説明。空なら該当 DOM ごと出力されない |

`難易度` と `単価（円）` は**チャレンジタスクでのみ**使用される。基本タスクは `タスク名` と `備考` しか読まない。

### 2.3 行の採否ルール

| 条件 | 結果 |
| --- | --- |
| `タスク名` が空 | 破棄（無言） |
| `タイプ` = `基本` | 基本タスクとして採用 |
| `タイプ` = `チャレンジ` | チャレンジタスクとして採用 |
| `タイプ` が上記以外・空 | 破棄（無言） |

**いずれの破棄も警告を出さない。** そのため、Notion 側で列名を変更したり、タイプの選択肢名を変えたりすると、エラーにならず「出力が空になる」という形で現れる。障害調査時は `load_tasks()`（`generate.py:76-98`）を最初に確認すること。

### 2.4 並び順

Notion API のクエリ結果の順序をそのまま使用する（`sorts` を指定していないため、Notion 側のデフォルト順）。この順序は後述するポスターの**色・アイコンの割り当てに直結する**（5.3 節）。

## 3. 処理仕様

`generate.py` は 3 層構造になっている。

### 3.1 第1層：Notion 取得

#### `notion_query_database(database_id) -> list[dict]`

| 項目 | 内容 |
| --- | --- |
| エンドポイント | `POST https://api.notion.com/v1/databases/{id}/query` |
| API バージョン | `Notion-Version: 2022-06-28`（固定） |
| 認証 | `Authorization: Bearer {NOTION_TOKEN}` |
| ページサイズ | 100 |
| ページング | レスポンスの `has_more` が真の間、`next_cursor` を `start_cursor` に設定して繰り返す |
| 戻り値 | 全ページの `results` を連結した配列 |

#### エラーハンドリング

HTTP エラーは `fail_with_api_error()` が受け取り、原因の見当がつくメッセージを stderr に出して `exit 1` する。トレースバックは出さない。

| ステータス | 表示するヒント |
| --- | --- |
| 401 | トークンが無効か期限切れ |
| 403 | トークンに読み取り権限がない |
| 404 | DB ID が違う、または Notion 側でインテグレーションを「コネクト」していない |
| 429 | レート制限。時間をおいて再実行 |
| その他 | ステータスコードと API の応答本文のみ表示 |

いずれの場合も、API のレスポンス JSON に含まれる `message` を併記する。接続自体に失敗した場合（`URLError`）は「Notion APIに接続できませんでした（理由）」を表示して `exit 1` する。

#### プロパティ抽出ヘルパー

| 関数 | 対象型 | 戻り値 | 値が無いとき |
| --- | --- | --- | --- |
| `get_prop_text(props, name)` | title / rich_text | 全要素の `plain_text` を連結した文字列 | `""` |
| `get_prop_select(props, name)` | select | 選択肢の `name` | `""` |
| `get_prop_number(props, name)` | number | 数値 | `0`（`or 0` により、値が `0` や `None` のとき `0`） |

`get_prop_text` は `prop["type"]` を見て動的に配列を取り出すため、title と rich_text のどちらでも同じように扱える。

### 3.2 第2層：ドメイン変換

#### `load_tasks() -> tuple[list, list]`

Notion のページ配列を、2 種類のタスク辞書リストへ振り分ける。

**基本タスク**
```python
{"name": str, "note": str}
```

**チャレンジタスク**
```python
{"name": str, "note": str, "star": str, "price": int}
```

`price` は `int()` で整数化されるため、小数を入力した場合は**切り捨て**られる。`star` は空文字なら `"★"` にフォールバックする。

戻り値は `(basic_tasks, challenge_tasks)` のタプル。`load_sample_tasks()` は同じ形のタプルを `data/sample_tasks.json` から読んで返す。

#### `warn_on_task_counts(basic_tasks, challenge_tasks)`

件数から異常を検知して stderr に**警告**を出す。あくまで警告であり、生成処理は続行する（`exit` しない）。

| 条件 | 警告内容 |
| --- | --- |
| 両方 0 件 | プロパティ名・選択肢名の変更を疑うよう促す（2.3 節の無言破棄への対策） |
| 基本タスクのみ 0 件 | ポスターが空になる旨 |
| チャレンジタスクのみ 0 件 | スタンプカードが空になる旨 |
| 基本 > `BASIC_TASK_LIMIT`（8） | A4 縦に収まらない可能性。印刷プレビューでの確認を促す |
| チャレンジ > `CHALLENGE_TASK_LIMIT`（14） | A4 横に収まらない可能性。同上 |

#### 来歴（provenance）

`build_provenance(source)` が、生成時刻（JST）・データ源（`notion` / `sample`）・コミット SHA を持つ辞書を返す。SHA は環境変数 `GITHUB_SHA` を優先し、無ければ `git rev-parse --short HEAD` を試み、それも失敗すれば空文字とする。

### 3.3 第3層：HTML 生成

2 つのビルダー関数はいずれも**引数のタスクリストのみに依存する純粋関数**であり、ネットワークにもファイルシステムにもアクセスしない。完全な HTML 文書を文字列として返す。

| 関数 | 入力 | 出力 |
| --- | --- | --- |
| `build_stamp_print_html(challenge_tasks, prov)` | チャレンジタスク＋来歴 | A4 横のスタンプカード |
| `build_basic_poster_html(basic_tasks, prov)` | 基本タスク＋来歴 | A4 縦のポスター |

いずれも f-string 内に CSS を直接書いているため、**リテラルの波括弧は `{{` `}}` と二重にする必要がある**。

`main()` はこの 2 つを呼び出してファイルに書き、加えて `index.html`（f-string のベタ書き）と `tasks.json` を生成する。

#### HTML エスケープ

Notion 由来の文字列は、HTML に埋め込む直前に必ず `esc()` を通す。`esc()` は `html.escape(str(value), quote=True)` の薄いラッパで、`<` `>` `&` `"` `'` を実体参照に変換する。

対象は `name` / `note` / `star` の 3 項目。`price` は `int` に変換済みのため対象外。

> **改修時の注意**：テンプレートに新しい値を差し込む場合、Notion 由来であれば必ず `esc()` で包むこと。包み忘れると、タスク名に `<` を含めただけでマークアップが壊れる（旧実装の既知の不具合）。

## 4. 出力仕様

### 4.1 出力ファイル

出力先ディレクトリは `output/`（定数 `OUTPUT_DIR`）。`os.makedirs(exist_ok=True)` で毎回作成され、既存ファイルは上書きされる。文字コードは全て UTF-8。

| ファイル名 | 内容 | 用紙 |
| --- | --- | --- |
| `index.html` | 印刷ページと JSON へのリンク集 | — |
| `stamp_print.html` | チャレンジタスクのスタンプカード | A4 横 |
| `basic_tasks_poster.html` | 基本タスクのポスター | A4 縦 |
| `tasks.json` | 機械可読なタスクデータ | — |

`output/` は `.gitignore` で除外されている。

### 4.1.1 `tasks.json` の構造

```json
{
  "generated_at": "2026-08-16T21:30:00+09:00",
  "source": "notion",
  "commit": "2160986",
  "counts": { "basic": 6, "challenge": 7 },
  "basic_tasks":     [{ "name": "...", "note": "..." }],
  "challenge_tasks": [{ "name": "...", "note": "...", "star": "★★", "price": 50 }]
}
```

`ensure_ascii=False` / `indent=2` で出力するため、日本語がそのまま読める。

**`NOTION_DATABASE_ID` は意図的に含めていない。** このファイルは GitHub Pages 上で公開されるため、データベースの識別子を出さない方針とする。

### 4.2 共通の設計方針

- **完全自己完結**：CSS は全て `<style>` 内にインライン展開。外部参照は Google Fonts（`Noto Sans JP`）の 1 リンクのみ。JavaScript は印刷ボタンの `onclick="window.print()"` だけ。
- **印刷が主・画面は下見**：寸法は全て `mm` / `pt`。各ページに `@media print` ブロックがあり、`@page { size: A4 landscape|portrait; margin: 0 }` を指定する。
- 画面表示時のみ、`.print-controls`（印刷ボタンと注記）を表示。印刷時は `display: none !important` で消える。

### 4.2.1 来歴の埋め込み

3 つの HTML すべてが、`<head>` 内に以下のメタタグを持つ。レイアウトには影響しない。

```html
<meta name="generator" content="otetsudai-card">
<meta name="date" content="2026-08-16T21:30:00+09:00">
<meta name="source" content="notion (commit 2160986)">
```

加えて、画面表示時のみ見える位置に「Notionのデータから自動生成されました（2026年08月16日 21:30 / 2160986）」の形式で注記を出す。**印刷時には出ない**（`.print-controls` / `.updated` に含まれるため）。紙面のレイアウトを変えないための判断である。

### 4.3 実行ログ

標準出力に以下を出力する（`--sample` 指定時は先頭にサンプルデータ使用の旨が付く）。

```
基本タスク: {n}件, チャレンジタスク: {m}件
生成完了: output/index.html, stamp_print.html, basic_tasks_poster.html, tasks.json
```

警告およびエラーは stderr に出力する（3.2 節）。

## 5. 各出力ページの詳細仕様

### 5.1 スタンプカード（`stamp_print.html`）

#### 5.1.1 構成

1 枚のシートは「ヘッダー」「メインテーブル」「計算セクション」の 3 ブロックからなる。**同一のシートを 2 回出力する**（`sheet() + sheet()`）ため、1 回の印刷で 2 部得られる。1 枚目には `page-break-after: always` が効き、最後のシートは `page-break-after: avoid`。

#### 5.1.2 ヘッダー

- タイトル「⭐ おてつだいスタンプカード」
- 記入欄：「なまえ」（30mm）、「年」（13mm）、「月」（9mm）の下線

#### 5.1.3 メインテーブル

固定 36 列（3 + 31 + 2）。列構成と幅は以下の通り。

| 列 | CSS クラス | 幅 | 内容 |
| --- | --- | --- | --- |
| 1 | `col-task` | 36mm | おてつだい（タスク名＋備考） |
| 2 | `col-star` | 7mm | むず（難易度） |
| 3 | `col-price` | 10mm | 1かい（単価） |
| 4〜34 | `col-date` | 6.5mm × 31 | 日付 1〜31 のスタンプ欄 |
| 35 | `col-count` | 9mm | かい数 |
| 36 | `col-earn` | 12mm | ごうけい |

行の構成は「タスク行 × タスク数」→「セクションラベル行（じゆうきにゅう）」→「自由記入行 × 3」（`free_rows = 3`）。

> **改修時の注意（3 か所連動）**
> 列構成を変える場合、以下の 3 か所を必ず同時に修正すること。
> 1. `<colgroup>` 内の `<col>` 要素（`generate.py:186-193`）
> 2. `col.col-*` の CSS 幅指定（`generate.py:287-292`）
> 3. セクションラベル行の `colspan="{3 + len(dates) + 2}"`（`generate.py:207`）

列幅の合計は 36 + 7 + 10 + (6.5 × 31) + 9 + 12 = **275.5mm**。印刷時のシート内幅は A4 横 297mm − 左右パディング 8mm × 2 = 281mm なので収まる。一方、画面表示時は `.sheet` 幅 277mm − パディング 7mm × 2 = 263mm となり列幅の合計を下回るため、ブラウザが圧縮して表示する。**画面上で列が詰まって見えるのは仕様どおりであり、印刷プレビューで確認すること。**

#### 5.1.4 計算セクション

- 左側：タスクごとに「タスク名 / 単価円 × □ = □ 円」の行を 2 列グリッドで配置。自由記入行の分も 3 行追加される。
- 右側：
  - 「🔒 かならずもらえる **500円**」— 金額はモジュール定数 `FIXED_ALLOWANCE`（初期値 `500`）で定義される。Notion からは変更できず、コードの修正が必要。
  - 「⭐ おてつだい合計」記入欄
  - 「合計」記入欄

### 5.2 ポスター（`basic_tasks_poster.html`）

#### 5.2.1 構成

- ヘッダー：🏠 / 「きほんのお手伝い」/ 「これは毎日やること。家族の一員としての大事なしごと。」
- 記入欄：「なまえ」（50mm 下線）
- タスクカードのリスト（基本タスクの件数分）
- フッター：⭐ ⭐ ⭐ とチャレンジへの誘導文

用紙サイズは幅 190mm × 最小高さ 270mm（印刷時は `width: 100%` / `min-height: 100vh`）。

#### 5.2.2 タスクカード

各カードは「アイコン（28pt）＋ タスク名（14pt / 900）＋ 備考（8.5pt）」で構成され、左端に 5px のカラーボーダーが付く。

### 5.3 色とアイコンの割り当てロジック

```python
colors = ["c1", "c2", "c3", "c4", "c5", "c6"]                       # 6 色
icons  = ["🧹","👕","🧺","🍽️","🥢","🗑️","🧴","🧽","📚","🪥"]        # 10 種
color = colors[i % len(colors)]
icon  = icons[i % len(icons)]
```

`i` は**リスト内での位置（インデックス）**である。したがって、

- 色は 6 件周期、アイコンは 10 件周期で循環する
- **タスクの内容とアイコンには一切関係がない**（「そうじ」に 🧹 が付くのは偶然、または並び順の調整の結果）
- Notion 上でタスクを並べ替えたり、途中に 1 件追加したりすると、**以降の全タスクの色とアイコンがずれる**

色の定義：

| クラス | 背景 | ボーダー |
| --- | --- | --- |
| `c1` | `#fff7ed` | `#fb923c`（オレンジ） |
| `c2` | `#fdf4ff` | `#c084fc`（紫） |
| `c3` | `#f0fdf4` | `#4ade80`（緑） |
| `c4` | `#eff6ff` | `#60a5fa`（青） |
| `c5` | `#fff1f2` | `#fb7185`（ピンク） |
| `c6` | `#fefce8` | `#facc15`（黄） |

### 5.4 インデックスページ（`index.html`）

`main()` 内にベタ書きされた静的 HTML。2 つのリンクボタンを縦に並べただけの構成で、タスクデータには依存しない（生成のたびに同一内容になる）。

## 6. 実行仕様

### 6.1 ローカル実行

```bash
NOTION_TOKEN=ntn_... NOTION_DATABASE_ID=<32桁> python generate.py
```

生成後、`output/index.html` をブラウザで開いて確認する。**レイアウトの検証はブラウザの印刷プレビューで行うこと**（5.1.3 参照）。

#### 認証情報なしでの実行（サンプルモード）

```bash
python generate.py --sample
```

`data/sample_tasks.json`（基本 6 件 / チャレンジ 7 件）を入力として、通常と同じ 4 ファイルを生成する。Notion のアカウント・トークンは不要。第三者が動作を再現・検証する場合と、レイアウトを調整する場合の両方でこれを使う。

HTML ビルダーはタスクリストと来歴のみに依存する純粋関数のため、REPL から直接呼び出して確認することもできる。

```python
import generate as g
html = g.build_basic_poster_html(
    [{"name": "くつをそろえる", "note": "げんかんで"}],
    g.build_provenance("sample"),
)
```

## 8. OKF（オープンナレッジ）観点の評価

本章は OKF の [Open Definition](https://opendefinition.org/) — 「オープンなデータ・コンテンツとは、誰もが自由に**利用・改変・再配布**できるもの」— を基準に、本プロジェクトの現状を評価する。

### 8.1 評価サマリ

| 評価軸 | 現状 | 判定 |
| --- | --- | --- |
| オープンライセンス | コードは MIT、ドキュメントは CC BY 4.0 | ✓ 適合 |
| オープンフォーマット | Python / HTML / CSS / JSON。プロプライエタリ形式なし | ✓ 適合 |
| 入手性（アクセス） | GitHub Pages で URL 一つ、無償・登録不要 | ✓ 適合 |
| 機械可読性 | `tasks.json` を HTML と同時に公開 | ✓ 適合 |
| 再現性 | 依存ゼロ。`--sample` で第三者も認証情報なしに実行できる | ✓ 適合 |
| 来歴・出所の明示 | 全出力に生成日時・データ源・コミット SHA を埋め込み | ✓ 適合 |

### 8.2 ライセンス

Open Definition の中核要件は「オープンライセンスの明示」である。ライセンス表示のないコードは著作権法上「全ての権利を著作者が留保」した状態となり、リポジトリが Public でも第三者は法的に複製・改変・再配布ができない。本プロジェクトは以下の構成でこれを満たす。

| 対象 | ライセンス | 選定理由 |
| --- | --- | --- |
| コード（`generate.py`、ワークフロー、サンプルデータ） | MIT License | 制約が少なく、小規模ツールの事実上の標準 |
| ドキュメント（`README.md`、`docs/`） | CC BY 4.0 | OKF が Open Definition 準拠として認定しているライセンス |

生成された HTML・JSON の著作権は、それを生成した主体（＝入力データの持ち主）に帰属する。本リポジトリのライセンスは生成物の内容には及ばない。この区分は `README.md` に明記している。

### 8.3 適合の根拠

#### オープンフォーマット

入力は Notion API（JSON）、処理は Python、出力は HTML / CSS / JSON。閲覧・改変に専用ソフトを必要とする形式は一つも使っていない。

#### 再現性

外部パッケージへの依存がゼロであり、`pip install` を必要としない。Python 3.11 さえあれば長期にわたり同じ結果が得られる。加えて `--sample` により、**Notion のアカウントを持たない第三者でもクローン直後に実行・検証できる**（Open Definition が求める「検証可能性」に直結する）。

サンプルデータを自動フォールバックにせず明示的なオプトインとしたのは、CI での設定漏れ時に架空のデータが公開されるのを防ぐためである（2.1.1 節）。

#### 機械可読性

`tasks.json` を HTML と同じディレクトリに出力し、Pages 上で公開する。印刷用 HTML をスクレイピングせずにデータを再利用できる。`ensure_ascii=False` により日本語がそのまま読める。

#### 来歴（provenance）

全ての出力に、生成日時（JST・ISO 8601）、データ源（`notion` / `sample`）、コミット SHA を埋め込む（4.2.1 節、4.1.1 節）。印刷された紙がいつ時点のものか、どのコードから生成されたかを後から特定できる。

### 8.4 入力データの扱い（意図的に非公開）

Notion データベースは私的な家庭内データであり、公開しない。これは Open Definition への不適合ではなく、**公開対象の線引き**である。

- 公開するもの：ツール（コード）、生成された HTML と `tasks.json`、架空のサンプルデータ
- 公開しないもの：Notion データベース本体、`NOTION_TOKEN`、`NOTION_DATABASE_ID`

`tasks.json` に `NOTION_DATABASE_ID` を含めないのはこの方針によるもの（4.1.1 節）。`data/sample_tasks.json` は実在の家庭のデータではなく、すべて架空の内容である。この区分は `README.md` にも明記している。

### 8.5 適用しない項目

Open Definition には「データ全体をバルクでダウンロードできること」という要件もあるが、本プロジェクトの成果物は 4 ファイルの静的ファイルであり、リポジトリのクローンまたは Pages からの個別取得で十分に満たされる。追加対応は不要と判断する。
