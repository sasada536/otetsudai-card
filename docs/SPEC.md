## 1. システム概要

### 1.1 目的

家庭内の「おてつだい制度」を運用するため、Notion 上で管理しているタスク一覧から、**印刷して壁に貼る／記入する紙**を自動生成する。Notion を編集するだけで紙が更新される状態を作り、手作業でのレイアウト修正を不要にすることが目的。

### 1.2 全体構成

```
┌─────────────────┐
│ Notion DB       │  「おてつだいタスク一覧」
│ （手動で編集）   │  ※非公開・APIトークンが必要
└────────┬────────┘
         │ Notion API (HTTPS/POST)
         ↓
┌─────────────────┐
│ generate.py     │  Python 3.11 / 標準ライブラリのみ
│ （GitHub Actions │  手動実行（workflow_dispatch）
│   上で実行）     │
└────────┬────────┘
         │ 静的ファイル書き出し
         ↓
┌─────────────────┐
│ output/         │  index.html
│ （3ファイル）    │  stamp_print.html
│                 │  basic_tasks_poster.html
└────────┬────────┘
         │ actions/upload-pages-artifact → deploy-pages
         ↓
┌─────────────────┐
│ GitHub Pages    │  https://<user>.github.io/<repo>/
│ （公開）         │  → iPhone 等のブラウザで開いて印刷
└─────────────────┘
```

### 1.3 構成要素

| ファイル | 役割 | 規模 |
| --- | --- | --- |
| `generate.py` | 取得・変換・HTML生成のすべて | 約 520 行 |
| `.github/workflows/generate.yml` | 実行と Pages への公開 | 約 50 行 |
| `README.md` | エンドユーザー向けセットアップ手順 | — |
| `CLAUDE.md` | Claude Code 向けの開発ガイド | — |
| `docs/SPEC.md` | 本書 | — |

外部ライブラリへの依存は**ゼロ**（`os` / `sys` / `json` / `urllib.request` のみ）。`requirements.txt`、`package.json` 等のマニフェストは存在しない。ビルド手順・テストコードも存在しない。

## 2. 入力仕様

### 2.1 環境変数

| 変数名 | 必須 | 内容 | 未設定時の挙動 |
| --- | --- | --- | --- |
| `NOTION_TOKEN` | ○ | Notion Internal Integration Secret（`ntn_` 始まり） | エラーメッセージを stderr に出力し `exit 1` |
| `NOTION_DATABASE_ID` | ○ | 対象データベースの ID（ハイフンなし 32 桁） | 同上 |

いずれもモジュール読み込み時（`generate.py:16-17`）に `os.environ.get()` で取得され、モジュール定数として保持される。存在チェックは `main()` の冒頭（`generate.py:474`）で行われる。

### 2.2 Notion データベースのスキーマ

`load_tasks()` が参照するプロパティは以下の 5 つ。**プロパティ名（日本語）はコードにハードコードされている。**

| プロパティ名 | Notion 型 | 必須 | 用途 |
| --- | --- | --- | --- |
| `タスク名` | title または rich_text | ○ | タスクの名称。空の行はスキップされる |
| `タイプ` | select | ○ | `基本` / `チャレンジ` のいずれか。それ以外の値の行は無視される |
| `難易度` | select | — | 星の表示（例: `★★`）。空の場合は `★` が入る |
| `単価（円）` | number | — | 1 回あたりの金額。空の場合は `0` |
| `備考` | rich_text | — | 補足説明。空なら該当 DOM ごと出力されない |

`難易度` と `単価（円）` は**チャレンジタスクでのみ**使用される。基本タスクは `タスク名` と `備考` しか読まない。

### 2.3 行の採否ルール

| 条件 | 結果 |
| --- | --- |
| `タスク名` が空 | 破棄（無言） |
| `タイプ` = `基本` | 基本タスクとして採用 |
| `タイプ` = `チャレンジ` | チャレンジタスクとして採用 |
| `タイプ` が上記以外・空 | 破棄（無言） |

**いずれの破棄も警告を出さない。** そのため、Notion 側で列名を変更したり、タイプの選択肢名を変えたりすると、エラーにならず「出力が空になる」という形で現れる。障害調査時は `load_tasks()`（`generate.py:76-98`）を最初に確認すること。

### 2.4 並び順

Notion API のクエリ結果の順序をそのまま使用する（`sorts` を指定していないため、Notion 側のデフォルト順）。この順序は後述するポスターの**色・アイコンの割り当てに直結する**（5.3 節）。

## 3. 処理仕様

`generate.py` は 3 層構造になっている。

### 3.1 第1層：Notion 取得

#### `notion_query_database(database_id) -> list[dict]`

| 項目 | 内容 |
| --- | --- |
| エンドポイント | `POST https://api.notion.com/v1/databases/{id}/query` |
| API バージョン | `Notion-Version: 2022-06-28`（固定） |
| 認証 | `Authorization: Bearer {NOTION_TOKEN}` |
| ページサイズ | 100 |
| ページング | レスポンスの `has_more` が真の間、`next_cursor` を `start_cursor` に設定して繰り返す |
| 戻り値 | 全ページの `results` を連結した配列 |

**エラーハンドリングは実装されていない。** `urllib.request.urlopen()` を `try` で囲んでいないため、認証エラー（401）、DB が見つからない（404）、レート制限（429）、ネットワーク断のいずれもトレースバックを出して異常終了する。CI 上ではジョブ失敗として現れる。

#### プロパティ抽出ヘルパー

| 関数 | 対象型 | 戻り値 | 値が無いとき |
| --- | --- | --- | --- |
| `get_prop_text(props, name)` | title / rich_text | 全要素の `plain_text` を連結した文字列 | `""` |
| `get_prop_select(props, name)` | select | 選択肢の `name` | `""` |
| `get_prop_number(props, name)` | number | 数値 | `0`（`or 0` により、値が `0` や `None` のとき `0`） |

`get_prop_text` は `prop["type"]` を見て動的に配列を取り出すため、title と rich_text のどちらでも同じように扱える。

### 3.2 第2層：ドメイン変換

#### `load_tasks() -> tuple[list, list]`

Notion のページ配列を、2 種類のタスク辞書リストへ振り分ける。

**基本タスク**
```python
{"name": str, "note": str}
```

**チャレンジタスク**
```python
{"name": str, "note": str, "star": str, "price": int}
```

`price` は `int()` で整数化されるため、小数を入力した場合は**切り捨て**られる。`star` は空文字なら `"★"` にフォールバックする。

戻り値は `(basic_tasks, challenge_tasks)` のタプル。

### 3.3 第3層：HTML 生成

2 つのビルダー関数はいずれも**引数のタスクリストのみに依存する純粋関数**であり、ネットワークにもファイルシステムにもアクセスしない。完全な HTML 文書を文字列として返す。

| 関数 | 入力 | 出力 |
| --- | --- | --- |
| `build_stamp_print_html(challenge_tasks)` | チャレンジタスク | A4 横のスタンプカード |
| `build_basic_poster_html(basic_tasks)` | 基本タスク | A4 縦のポスター |

いずれも f-string 内に CSS を直接書いているため、**リテラルの波括弧は `{{` `}}` と二重にする必要がある**。

`main()` はこの 2 つを呼び出してファイルに書き、加えて `index.html` を（f-string のベタ書きで）生成する。

## 4. 出力仕様

### 4.1 出力ファイル

出力先ディレクトリは `output/`（定数 `OUTPUT_DIR`）。`os.makedirs(exist_ok=True)` で毎回作成され、既存ファイルは上書きされる。文字コードは全て UTF-8。

| ファイル名 | 内容 | 用紙 |
| --- | --- | --- |
| `index.html` | 2 つの印刷ページへのリンク集 | — |
| `stamp_print.html` | チャレンジタスクのスタンプカード | A4 横 |
| `basic_tasks_poster.html` | 基本タスクのポスター | A4 縦 |

`output/` は Git 管理外だが、**`.gitignore` が存在しないため、意図せず `git add` される余地がある**。

### 4.2 共通の設計方針

- **完全自己完結**：CSS は全て `<style>` 内にインライン展開。外部参照は Google Fonts（`Noto Sans JP`）の 1 リンクのみ。JavaScript は印刷ボタンの `onclick="window.print()"` だけ。
- **印刷が主・画面は下見**：寸法は全て `mm` / `pt`。各ページに `@media print` ブロックがあり、`@page { size: A4 landscape|portrait; margin: 0 }` を指定する。
- 画面表示時のみ、`.print-controls`（印刷ボタンと注記）を表示。印刷時は `display: none !important` で消える。

### 4.3 実行ログ

標準出力に以下の 2 行を出力する。

```
基本タスク: {n}件, チャレンジタスク: {m}件
生成完了: output/index.html, stamp_print.html, basic_tasks_poster.html
```

## 5. 各出力ページの詳細仕様

### 5.1 スタンプカード（`stamp_print.html`）

#### 5.1.1 構成

1 枚のシートは「ヘッダー」「メインテーブル」「計算セクション」の 3 ブロックからなる。**同一のシートを 2 回出力する**（`sheet() + sheet()`）ため、1 回の印刷で 2 部得られる。1 枚目には `page-break-after: always` が効き、最後のシートは `page-break-after: avoid`。

#### 5.1.2 ヘッダー

- タイトル「⭐ おてつだいスタンプカード」
- 記入欄：「なまえ」（30mm）、「年」（13mm）、「月」（9mm）の下線

#### 5.1.3 メインテーブル

固定 36 列（3 + 31 + 2）。列構成と幅は以下の通り。

| 列 | CSS クラス | 幅 | 内容 |
| --- | --- | --- | --- |
| 1 | `col-task` | 36mm | おてつだい（タスク名＋備考） |
| 2 | `col-star` | 7mm | むず（難易度） |
| 3 | `col-price` | 10mm | 1かい（単価） |
| 4〜34 | `col-date` | 6.5mm × 31 | 日付 1〜31 のスタンプ欄 |
| 35 | `col-count` | 9mm | かい数 |
| 36 | `col-earn` | 12mm | ごうけい |

行の構成は「タスク行 × タスク数」→「セクションラベル行（じゆうきにゅう）」→「自由記入行 × 3」（`free_rows = 3`）。

> **改修時の注意（3 か所連動）**
> 列構成を変える場合、以下の 3 か所を必ず同時に修正すること。
> 1. `<colgroup>` 内の `<col>` 要素（`generate.py:186-193`）
> 2. `col.col-*` の CSS 幅指定（`generate.py:287-292`）
> 3. セクションラベル行の `colspan="{3 + len(dates) + 2}"`（`generate.py:207`）

列幅の合計は 36 + 7 + 10 + (6.5 × 31) + 9 + 12 = **275.5mm**。印刷時のシート内幅は A4 横 297mm − 左右パディング 8mm × 2 = 281mm なので収まる。一方、画面表示時は `.sheet` 幅 277mm − パディング 7mm × 2 = 263mm となり列幅の合計を下回るため、ブラウザが圧縮して表示する。**画面上で列が詰まって見えるのは仕様どおりであり、印刷プレビューで確認すること。**

#### 5.1.4 計算セクション

- 左側：タスクごとに「タスク名 / 単価円 × □ = □ 円」の行を 2 列グリッドで配置。自由記入行の分も 3 行追加される。
- 右側：
  - 「🔒 かならずもらえる **500円**」— **この金額はコードにハードコードされている**（`generate.py:220`）。Notion では変更できない。
  - 「⭐ おてつだい合計」記入欄
  - 「合計」記入欄

### 5.2 ポスター（`basic_tasks_poster.html`）

#### 5.2.1 構成

- ヘッダー：🏠 / 「きほんのお手伝い」/ 「これは毎日やること。家族の一員としての大事なしごと。」
- 記入欄：「なまえ」（50mm 下線）
- タスクカードのリスト（基本タスクの件数分）
- フッター：⭐ ⭐ ⭐ とチャレンジへの誘導文

用紙サイズは幅 190mm × 最小高さ 270mm（印刷時は `width: 100%` / `min-height: 100vh`）。

#### 5.2.2 タスクカード

各カードは「アイコン（28pt）＋ タスク名（14pt / 900）＋ 備考（8.5pt）」で構成され、左端に 5px のカラーボーダーが付く。

### 5.3 色とアイコンの割り当てロジック

```python
colors = ["c1", "c2", "c3", "c4", "c5", "c6"]                       # 6 色
icons  = ["🧹","👕","🧺","🍽️","🥢","🗑️","🧴","🧽","📚","🪥"]        # 10 種
color = colors[i % len(colors)]
icon  = icons[i % len(icons)]
```

`i` は**リスト内での位置（インデックス）**である。したがって、

- 色は 6 件周期、アイコンは 10 件周期で循環する
- **タスクの内容とアイコンには一切関係がない**（「そうじ」に 🧹 が付くのは偶然、または並び順の調整の結果）
- Notion 上でタスクを並べ替えたり、途中に 1 件追加したりすると、**以降の全タスクの色とアイコンがずれる**

色の定義：

| クラス | 背景 | ボーダー |
| --- | --- | --- |
| `c1` | `#fff7ed` | `#fb923c`（オレンジ） |
| `c2` | `#fdf4ff` | `#c084fc`（紫） |
| `c3` | `#f0fdf4` | `#4ade80`（緑） |
| `c4` | `#eff6ff` | `#60a5fa`（青） |
| `c5` | `#fff1f2` | `#fb7185`（ピンク） |
| `c6` | `#fefce8` | `#facc15`（黄） |

### 5.4 インデックスページ（`index.html`）

`main()` 内にベタ書きされた静的 HTML。2 つのリンクボタンを縦に並べただけの構成で、タスクデータには依存しない（生成のたびに同一内容になる）。

## 6. 実行仕様

### 6.1 ローカル実行

```bash
NOTION_TOKEN=ntn_... NOTION_DATABASE_ID=<32桁> python generate.py
```

生成後、`output/index.html` をブラウザで開いて確認する。**レイアウトの検証はブラウザの印刷プレビューで行うこと**（5.1.3 参照）。

#### 認証情報なしでレイアウトを調整する方法

`load_tasks()` を一時的にリテラルのリストを返すよう差し替えれば、Notion に接続せずに HTML 生成を確認できる。HTML ビルダーはタスクリストのみに依存する純粋関数のため、この差し替えで完全に動作する。

```python
def load_tasks():
    return (
        [{"name": "くつをそろえる", "note": "げんかんで"}],
        [{"name": "おふろそうじ", "note": "", "star": "★★", "price": 50}],
    )
```

### 6.2 GitHub Actions（`.github/workflows/generate.yml`）

| 項目 | 設定 |
| --- | --- |
| ワークフロー名 | おてつだいカード生成 |
| トリガー | `workflow_dispatch`（手動のみ） |
| 定期実行 | `schedule: cron "0 0 1 * *"`（毎月 1 日 09:00 JST）が記述されているが**コメントアウトされており無効** |
| ランナー | `ubuntu-latest` |
| Python | 3.11（`actions/setup-python@v5`） |
| 権限 | `contents: read` / `pages: write` / `id-token: write` |
| 同時実行制御 | `group: "pages"`、`cancel-in-progress: false` |

ジョブは 2 段構成。

1. **build** — チェックアウト → Python セットアップ → `python generate.py` 実行（Secrets を環境変数に注入）→ `output/` を `actions/upload-pages-artifact@v3` でアップロード
2. **deploy** — `needs: build`。`actions/deploy-pages@v4` で GitHub Pages 環境へ公開

`NOTION_TOKEN` / `NOTION_DATABASE_ID` はリポジトリの Actions Secrets として設定されている必要がある。

### 6.3 運用フロー

1. Notion でタスクを編集する
2. GitHub の Actions タブ →「Run workflow」（iPhone の GitHub アプリからも可）
3. 約 1 分後、Pages の URL を開く
4. 「印刷する」ボタンを押す

## 7. 非機能仕様・制約

### 7.1 非機能

| 項目 | 内容 |
| --- | --- |
| 実行時間 | 1 分程度（大半は CI のセットアップ時間） |
| コスト | 無料（GitHub Actions / Pages / Notion API いずれも無料枠内） |
| 依存 | Python 3.11 標準ライブラリのみ。外部パッケージ不要 |
| テスト | なし |
| リント / フォーマッタ | 設定なし |

### 7.2 既知の制約・注意点

| # | 内容 | 影響度 |
| --- | --- | --- |
| 1 | **HTML エスケープをしていない。** Notion のタスク名・備考に `<` `>` `&` が含まれると、マークアップが壊れる（`generate.py:109` ほか、全ての値が生のまま f-string に埋め込まれる） | 高 |
| 2 | **エラーハンドリングがない。** Notion API のエラーはトレースバックで異常終了する | 中 |
| 3 | Notion のプロパティ名が日本語でハードコードされており、列名変更が無言の空出力になる | 中 |
| 4 | 「かならずもらえる 500円」がハードコード。Notion から変更できない | 中 |
| 5 | ポスターの色・アイコンが並び順依存のため、タスクを 1 件追加すると以降が全てずれる | 低 |
| 6 | 日付は 1〜31 の固定。実際の月の日数（28〜30 日）を考慮しない | 低 |
| 7 | 基本タスクが多いとポスターが A4 縦に収まらない。件数の上限チェックはない | 低 |
| 8 | チャレンジタスクが多いとスタンプカードが A4 横に収まらない。同上 | 低 |
| 9 | `.gitignore` が無く、`output/` が誤ってコミットされうる | 低 |
| 10 | Google Fonts へのオンライン参照があるため、完全オフラインでは既定フォントで表示される | 低 |

## 8. OKF（オープンナレッジ）観点の評価

本章は OKF の [Open Definition](https://opendefinition.org/) — 「オープンなデータ・コンテンツとは、誰もが自由に**利用・改変・再配布**できるもの」— を基準に、本プロジェクトの現状を評価する。

### 8.1 評価サマリ

| 評価軸 | 現状 | 判定 |
| --- | --- | --- |
| オープンライセンス | LICENSE ファイルが存在しない | ✗ 不適合 |
| オープンフォーマット | Python / HTML / CSS。プロプライエタリ形式なし | ✓ 適合 |
| 入手性（アクセス） | GitHub Pages で URL 一つ、無償・登録不要 | ✓ 適合 |
| 機械可読性 | 出力は印刷用 HTML のみ。構造化データを公開していない | △ 部分的 |
| 再現性 | 依存ゼロだが、第三者は Notion 認証情報が無く再実行できない | △ 部分的 |
| 来歴・出所の明示 | 生成日時・データ源を出力に含めていない | △ 部分的 |

### 8.2 最重要の指摘：ライセンスが未設定

**リポジトリに `LICENSE` ファイルが存在しない。** 著作権法上、ライセンスの明示がないコードは既定で「全ての権利を著作者が留保」した状態であり、リポジトリが Public であっても第三者は法的に複製・改変・再配布ができない。

つまり、**現状は「ソースが見える」だけであり、Open Definition における「オープン」ではない。**

第三者に再利用させたい場合は、以下のいずれかを追加することで解消する。

| 対象 | 推奨ライセンス | 理由 |
| --- | --- | --- |
| コード（`generate.py` 等） | MIT または Apache-2.0 | 制約が少なく、小規模ツールの事実上の標準 |
| ドキュメント・生成物 | CC BY 4.0 または CC0 1.0 | OKF が Open Definition 準拠として認定している |

コードとコンテンツでライセンスを分ける場合は、`README.md` にその旨を明記する。

### 8.3 適合している点

- **オープンフォーマットのみを使用**：入力は Notion API（JSON）、処理は Python、出力は HTML/CSS。閲覧・改変に専用ソフトを必要とする形式は一つも使っていない。
- **依存ライブラリがゼロ**：`pip install` を一切必要としない。Python 3.11 さえあれば 10 年後でも同じ結果が得られる可能性が高く、再現性の観点では極めて強い設計。
- **入手性**：生成物は GitHub Pages 上に静的ファイルとして公開され、アカウント登録も課金もなく取得できる。
- **完全自己完結の HTML**：出力ファイルは単体でダウンロードして保存・再配布できる（Google Fonts のみ外部参照）。

### 8.4 改善余地

#### (1) 構造化データを併せて出力する

現在の出力は「印刷用 HTML」のみで、人間が読む前提の成果物である。第三者が中身のデータを再利用するには HTML をスクレイピングするしかない。`output/tasks.json`（または CSV）を同時に書き出せば、機械可読なオープンデータとして成立する。

`load_tasks()` の戻り値をそのまま `json.dump()` すれば実現でき、実装コストはごく小さい。

#### (2) 第三者が再現できるようにする

リポジトリをクローンしても、`NOTION_TOKEN` が無い第三者は `generate.py` を実行できない。サンプルデータ（`sample_tasks.json` 等）を同梱し、認証情報が無い場合はそれを読むフォールバックを設けると、誰でも動作を再現・検証できるようになる。これは 6.1 節の「認証情報なしでレイアウトを調整する方法」を正式な機能に格上げすることに等しい。

#### (3) 来歴（provenance）を出力に含める

現在、生成された HTML には「いつ・どのデータから作られたか」の情報が無い（`index.html` の「Notionのデータから自動生成されています」という文言のみ）。生成日時と、可能であればソースのコミット SHA を埋め込むと、印刷物がどの時点のものか判別できる。

#### (4) データ源そのものは非公開である点の明示

Notion データベースは本質的に私的な家庭内データであり、公開すべきものではない。これは欠点ではなく設計上の妥当な判断だが、**「オープンなのはツールと生成物であって、入力データではない」**ことを README に明記しておくと、再利用者の誤解を防げる。

### 8.5 適用しない項目

Open Definition には「データ全体をバルクでダウンロードできること」という要件もあるが、本プロジェクトの成果物は 3 ファイルの静的 HTML であり、リポジトリのクローンまたは Pages からの個別取得で十分に満たされる。追加対応は不要と判断する。
